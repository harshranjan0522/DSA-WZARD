Two ways to store one

// adjacency list — O(V+E) space
A → B, D
B → A, C, E
C → B, F

// adjacency matrix — O(V²) space
   A B C
A  0 1 0
B  1 0 1
C  0 1 0

Pick by density. Real graphs are sparse (E ≈ V), so the list wins almost always. Use a matrix when you constantly ask "is u adjacent to v?" — that is O(1) on a matrix and O(deg V) on a list.
the concept

What are GRAPHS?

Drop the requirement that data be sequential or hierarchical, and you get the most general structure there is.

In plain english

A graph is dots and lines. The dots are vertices (nodes) and the lines are edges (connections).

A city map: junctions are vertices, roads are edges. A road with one-way traffic is a directed edge; a two-way road is undirected.

Put a number on an edge — distance, toll, latency — and the graph is weighted. That is when shortest path becomes an interesting question.

Unlike a tree, a graph can loop back on itself and can come in several disconnected pieces. Both facts are why every traversal needs a visited set.

Technically speaking

A graph is G = (V, E). Traversals cost O(V+E) with an adjacency list and O(V²) with a matrix, because a matrix forces you to inspect every possible edge.

BFS uses a queue and explores in rings of increasing distance, so on an unweighted graph the first time you reach a vertex is along a shortest path. DFS uses a stack (or recursion) and dives deep, which is what exposes cycles, components and topological order.

Add weights and BFS is no longer correct: use Dijkstra with a min-heap at O((V+E) log V) for non-negative weights, and Bellman-Ford at O(V·E) when negative edges are possible.

A DAG — directed, no cycles — is the shape dependencies form, and Kahn's algorithm sorts it in O(V+E). If a topological sort cannot consume every vertex, the graph had a cycle.

Real-life examples — graphs you already use

01Maps & navigation: junctions are vertices, roads are weighted edges, and "fastest route" is Dijkstra.
02Social networks: friendship is undirected; "follows" is directed. "People you may know" is a two-hop BFS.
03The web: pages are vertices, hyperlinks are directed edges — PageRank runs on exactly this graph.
04Build systems & course prerequisites: a DAG; the valid order is a topological sort, and a cycle means an impossible plan.
05Flight networks: airports and routes. "Fewest layovers" is BFS; "cheapest fare" is Dijkstra.
06Any grid puzzle: each cell is a vertex with up to four edges. Islands, flood fill and maze solving are all graph traversals.

BFS or DFS? Decide in one line

BFS (queue) — shortest path on unweighted edges, level-by-level questions, "minimum number of steps/minutes", nearest match.

DFS (stack / recursion) — does a path exist, connected components, cycle detection, topological sort, backtracking and flood fill.

Same code skeleton, same O(V+E). The only difference is whether the frontier is a queue or a stack — swap the container and the behaviour flips.

Always keep a visited set, and mark on enqueue rather than on dequeue. Skip either and a single cycle loops forever.

Operations on GRAPHS

Two traversals do most of the work; the named algorithms are variations on them.

Add a vertex

Append an empty neighbour list — O(1). On an adjacency matrix you must rebuild it at a new size, which is O(V²).

O(1)timeO(V²)matrix

Add an edge

adj[u].add(v). For an undirected graph you must add adj[v].add(u) too — forgetting the second line is the single most common graph bug.

O(1)time

Remove an edge

An adjacency list scans u's neighbours to find v, so it costs O(deg V). A matrix just writes a zero.

O(deg V)timeO(1)matrix

Check adjacency

"Is u connected to v?" — O(1) on a matrix, O(deg V) on a list. This one question is the main reason to ever choose a matrix.

O(1)timeO(deg V)list

BFS traversal

Queue-driven, expanding in rings of equal distance. Gives the shortest path in an unweighted graph and answers all "minimum steps" questions.

O(V+E)timeO(V)space

DFS traversal

Stack- or recursion-driven, diving as deep as possible before backtracking. The base for components, cycles, topological order and flood fill.

O(V+E)timeO(V)space

Connected components

Loop over every vertex; each unvisited one starts a fresh DFS and counts as a new component. Never assume the graph is a single piece.

O(V+E)time

Cycle detection

Undirected: DFS while ignoring the edge you arrived on — meeting a visited vertex means a cycle. Directed: track vertices on the current recursion stack, or check whether a topological sort consumes every vertex.

O(V+E)time

Shortest path — weighted

Dijkstra with a min-heap for non-negative weights; Bellman-Ford at O(V·E) when edges can be negative; Floyd-Warshall at O(V³) for all pairs.

O((V+E) log V)timeDijkstra

Topological sort (DAG)

Kahn's algorithm: repeatedly take a vertex with in-degree 0 and remove its outgoing edges. Produces a valid dependency order, or proves a cycle exists.

O(V+E)time

Minimum spanning tree

Cheapest set of edges that keeps everything connected. Kruskal sorts edges and uses union-find; Prim grows one tree with a min-heap.

O(E log E)time

Grid as a graph

Treat each cell as a vertex with up to four neighbours from dirs = [(1,0),(-1,0),(0,1),(0,-1)], bounds-checked. Islands, rotting oranges and maze solving are then plain BFS/DFS.

O(R·C)time
