A linear structure that follows Last-In, First-Out order: the most recently pushed element is the first one removed. Only one end is open — the top — and that single restriction is what makes every core operation O(1).

The whole interface

push(x) → put x on top
pop() → remove & return the top
peek() → read the top, keep it
isEmpty()→ top == -1 ?
size() → top + 1

That is it. Four or five methods, all O(1), and no way to reach into the middle. The power comes from the restriction, not from features.

You are already using one right now: every function call your program makes is pushed onto the call stack and popped when it returns.

the concept

What is a STACK?

One open end, two operations, and a surprising number of problems that collapse into it.

In plain english

Picture a stack of plates. You add a plate on top, and you take a plate from the top. You never pull one out of the middle.

The last plate you put down is the first one you pick up — that is Last-In First-Out, LIFO.

Because only the top ever moves, adding and removing are instant: no shifting, no searching, no scanning.

Anything that needs "the most recent thing first" is a stack: undo history, the browser back button, matching brackets in an editor, and recursion itself.

Technically speaking

A stack is an abstract data type with a single access point. Implement it over an array (fast, cache friendly, fixed or doubling capacity) or a linked list (no limit, one allocation per push).

An array-backed stack keeps a top index starting at -1. push is arr[++top] = x; pop is return arr[top--]. Both are O(1).

Two failure states matter: overflow (push onto a full fixed array) and underflow (pop from an empty stack). Guard with isFull() and isEmpty() — an unguarded pop is the classic crash.

The monotonic stack is the pattern that turns a family of O(n²) problems into O(n): keep indices in increasing or decreasing order, and resolve them the moment a violating element arrives. Each index is pushed and popped at most once.

Real-life examples — LIFO everywhere

01Plates in a canteen: the last washed plate sits on top and gets taken first.
02Browser history: "back" returns to the page you visited most recently, not the first one.
03Ctrl+Z: undo reverses your latest action; the editor keeps an undo stack and a redo stack.
04The call stack: main calls a calls b; b finishes first and pops. Infinite recursion is literally a stack overflow.
05Bracket matching: your editor pushes every opener and pops on the matching closer — leftovers mean unbalanced code.
06Bangles on a wrist: the last one slipped on is the first one that comes off.

Stack vs Queue in one line

Stack (LIFO) — newest out first. Use it when recency matters: undo, backtracking, depth-first search, expression evaluation.

Queue (FIFO) — oldest out first. Use it when fairness or order matters: scheduling, buffering, breadth-first search.

Swap a stack for a queue in a graph traversal and DFS becomes BFS. Nothing else in the code changes — that is how tightly the structure controls the behaviour.

Interview tell — "most recent", "nested", "matching", "undo", "next greater" ⇒ reach for a stack.

Operations on a STACK

Five O(1) primitives, plus the two application patterns that make stacks worth learning.

push(x) — insert

Place x on top: increment top, then write. On a fixed array check isFull() first or you get overflow; a dynamic stack doubles instead.

O(1)timeamortised on resize

pop() — remove

Read the top element and decrement top. Nothing shifts. Popping an empty stack is underflow — always guard it.

O(1)time

peek() / top()

Return the top without removing it. Mixing peek and pop up is a real bug source: one keeps the value, the other consumes it.

O(1)time

isEmpty() / isFull()

The two guards that make a stack safe: top == -1 means empty, top == capacity-1 means full. Cheap, and non-optional.

O(1)time

size()

top + 1 for an array-backed stack, or a maintained counter for a linked one. Never traverse to count.

O(1)time

search / contains

Not a stack operation. You would have to pop everything into a second stack and push it back, which is O(n) — if you need this often, a stack is the wrong structure.

O(n)time

Balanced brackets

Push every opener; on a closer, pop and check it matches. Empty stack on a closer, or leftovers at the end, means unbalanced input.

O(n)timeO(n)space

Monotonic stack

Keep indices in monotonic order and resolve them when a violating element arrives. Turns "next greater element", "daily temperatures" and "largest rectangle" from O(n²) into O(n).

O(n)time1 push + 1 pop each

Expression evaluation

Convert infix to postfix with an operator stack, then evaluate the postfix with a value stack: pop two, apply, push the result. This is how calculators actually work.

O(n)time

Iterative DFS & backtracking

Recursion uses the hidden call stack; swap in an explicit stack and you get the same traversal without any stack-overflow risk on deep inputs.

O(V+E)time
