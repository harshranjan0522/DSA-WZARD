A linear structure that operates on First-In, First-Out order: elements are enqueued at the rear and dequeued from the front, exactly like a real queue at a counter. Both ends are open, and both operations are O(1) — provided you implement it properly.

The whole interface

enqueue(x) → add at the rear
dequeue() → remove from the front
front() → read the oldest
rear() → read the newest
isEmpty() → size == 0 ?

The catch — a naive array queue that shifts every element left on dequeue is O(n). Move the index instead of the data and it is O(1). That is the entire reason circular queues exist.

Queues are what make BFS work, and BFS is what gives you shortest paths in an unweighted graph.

the concept

What is a QUEUE?

Fairness by construction: whoever waited longest is served next.

In plain english

Picture the line at a ticket counter. You join at the back; the person at the front gets served and leaves.

The first person to arrive is the first to leave — First-In First-Out, FIFO. The exact opposite of a stack.

Two ends are in play: the rear where things enter and the front where things leave. Track both with indices and neither operation ever touches the middle.

The naive mistake is shifting everyone forward when the front leaves. Real queues just move a marker for where the front now is — that is the circular queue.

Technically speaking

A queue keeps front and rear indices plus a size counter. enqueue advances the rear, dequeue advances the front. Nothing shifts.

In a circular queue both indices wrap with modulo: rear = (rear + 1) % capacity. Without the wrap, the slots freed at the front are lost forever and the queue reports "full" while half empty.

front == rear is ambiguous in a ring buffer — it can mean both full and empty — so keep an explicit size counter rather than guessing from the indices.

Variants specialise the idea: a deque opens both ends for insertion and removal, and a priority queue serves the highest priority first via a binary heap at O(log n) per operation.

Real-life examples — FIFO everywhere

01Ticket counter: arrive last, served last. No queue-jumping.
02Printer spooler: documents print in the order they were submitted.
03CPU scheduling: the OS keeps ready processes in a queue and gives each a turn — round robin.
04Call centre hold: "you are number 4 in the queue" is literally the front index distance.
05Message brokers (Kafka, RabbitMQ): producers enqueue events, consumers dequeue them in order.
06BFS: exploring a maze one ring of cells at a time — that ring is exactly the queue contents.

Why circular, concretely

Capacity 5. Enqueue P1…P5, then dequeue three times. A linear array queue now has three free slots at the front but rear is already at the wall — it refuses the next enqueue even though it is 40% empty.

A circular queue wraps rear back to index 0 and reuses those slots. Same memory, no waste, still O(1).

rear = (rear + 1) % capacity
front = (front + 1) % capacity

Operations on a QUEUE

Core operations are O(1); the variants trade that for extra ordering power.

enqueue(x) — insert at rear

Advance rear (wrapping with modulo in a circular queue) and write x. Check isFull() first on a fixed capacity.

O(1)time

dequeue() — remove from front

Read arr[front] then advance front. Only the index moves — shifting the array instead is the O(n) mistake.

O(1)timeO(n)naive

front() / peek()

Read the oldest element without removing it — useful for "is the next task ready?" checks before committing to a dequeue.

O(1)time

rear() / back()

Read the most recently enqueued element. Handy when a queue doubles as a sliding window.

O(1)time

isEmpty() / isFull()

Compare the size counter against 0 and capacity. Do not infer emptiness from front == rear — in a ring buffer that is ambiguous.

O(1)time

The circular wrap

(index + 1) % capacity. This one line is what lets a fixed array serve unlimited enqueue and dequeue cycles without ever shifting or leaking slots.

O(1)timemodulo arithmetic

search / contains

Linear scan from front to rear. As with stacks, if you need this often the queue is the wrong structure.

O(n)time

Priority queue push / pop

A binary heap keeps the extreme element at the root, sifting up on insert and down on removal. Order becomes priority instead of arrival.

O(log n)time

Deque operations

Insert and remove at both ends in O(1). Backs the monotonic-deque solution to sliding window maximum and doubles as both stack and queue.

O(1)timeboth ends

BFS traversal

The queue's killer app: enqueue the start, then repeatedly dequeue and enqueue unseen neighbours. Mark visited on enqueue. First arrival at a node is the shortest unweighted path to it.
